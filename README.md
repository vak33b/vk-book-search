# Поиск документов в сообществах ВКонтакте

Проект по эксплуатационной практике, ИУ6-62Б, 2026 год. Студент — Суворов Вакао Александр.

Приложение получает вложения публикаций выбранных сообществ VK, формирует каталог и позволяет искать документы через веб-интерфейс. Сервер написан на C++20 с использованием Drogon. Сбор данных и поиск запускаются отдельно: поисковый запрос обрабатывает уже полученный каталог.

## Возможности

- Сбор вложений из Proglib и BookFlow через `wall.get` и `wall.search`.
- Приём PDF, DJVU, DOC, TXT, FB2 и EPUB в каталог; извлечение текста реализовано только для PDF с текстовым слоем.
- Поиск по названию, публикации, аннотации и содержимому PDF.
- Фильтры по сообществу, автору, году и тегам, точное или частичное совпадение названия.
- Постраничная выдача и переход к исходной публикации VK.

Полный архив сообществ и весь ВКонтакте не охватываются. Неизвестные авторы и годы остаются незаполненными. OCR и чтение содержимого DJVU/DOC не реализованы. Индекс SQLite FTS5 создаётся в памяти на каждый запрос.

## Сборка на macOS Apple Silicon

Проверенная среда: AppleClang 17, CMake, Ninja, Drogon 1.9.13, ICU, SQLite и libcurl. Для Python-обработчика нужен Python 3 с модулем `venv` и зависимостями из `app/requirements.txt`.

На машине должны быть установлены инструменты командной строки Xcode и перечисленные библиотеки. Профиль `app/CMakePresets.json` рассчитан на Homebrew в `/opt/homebrew` и ICU в `/opt/homebrew/opt/icu4c@78`. Если версия ICU или расположение библиотек отличаются, исправьте `CMAKE_PREFIX_PATH` в профиле.

Все команды ниже выполняются из корня репозитория:

```sh
cmake --preset mac-arm64-debug -S app
cmake --build app/build/debug -j 4
ctest --test-dir app/build/debug --output-on-failure
```

Проверки ядра не требуют ключа VK, интернета или скачанных книг.

## Первый запуск

Для просмотра интерфейса с пустым каталогом:

```sh
mkdir -p app/data materials
cp app/data/catalog.example.json app/data/catalog.json
app/build/debug/vk_books serve .
```

Откройте `http://127.0.0.1:8081/`. Остановка — Control+C. Копировать пустой каталог следует только при первом запуске: повторная команда заменит собранные записи.

## Получение данных VK

1. Скопируйте `.env.example` в `.env` и укажите свой сервисный ключ после `VK_SERVICE_TOKEN=` без кавычек и пробелов.
2. Проверьте список сообществ в `config/vk-sources.example.json`.
3. Остановите сервер перед обновлением данных.

```sh
mkdir -p app/data materials
chmod 600 .env
app/build/debug/vk_books sync .
python3 -m venv app/.venv
app/.venv/bin/python -m pip install -r app/requirements.txt
app/.venv/bin/python scripts/extract_documents.py
app/build/debug/vk_books serve .
```

Сбор ограничен тремя страницами по 100 публикаций каждого метода на сообщество. Выдачи методов пересекаются; повторные вложения объединяются по ID. Доступность методов зависит от ключа и разрешений VK. На проверенном сервисном ключе `docs.search` и `docs.get` возвращали ошибку 28, поэтому они не используются для сбора.

Ключ, временные ссылки, скачанные файлы и извлечённые тексты исключены из Git. В репозитории нет библиотеки книг: пользователь получает доступные документы через VK со своим ключом.

## API

`GET /api/v1/books` принимает `q`, `scope`, `title`, `title_match`, `author`, `year`, `tag`, `community`, `limit`, `offset`. Области поиска: `all`, `title`, `post`, `annotation`, `body`. Несколько слов в `q` рассматриваются как одна фраза. Фильтры применяются совместно.

Другие маршруты: `GET /health`, `GET /api/v1/communities`, `GET /`. Неверный параметр возвращает HTTP 400, недоступность каталога — HTTP 503. Сервер слушает только `127.0.0.1:8081`.

## Проверки

Тест `search_contract` проверяет нормализацию, фильтры, области поиска, пагинацию, метаданные и допустимые расширения. Исторические результаты на реальных документах описаны в [протоколе](docs/validation.md). Интеграционные сценарии в `app/tests/*_smoke.py` требуют работающего сервера и соответствующего каталога; они не являются проверками пустой установки.
